# Phase 11 — Globus transfer runbook (ERA5 + AMIP)

Everything in Phase 11 that does **not** need Globus is already done or running:

| Dataset | State | Where |
|---|---|---|
| PLASIM sigma | ✅ converted | Delta (`12-104`) |
| PLASIM plev | ⏳ converting `12-104` | Derecho job `6681544` (raw already on Derecho — no Globus) |
| E3SM | ⏳ converting `2015-2049` | Derecho job `6681752` (raw already on Derecho — no Globus) |
| **ERA5** | ⛔ needs Globus | correct raw only on Delta `bgong1/data/h5data` |
| **AMIP** | ⛔ needs Globus | raw only on Delta `awikner/AMIP/h5` |

ERA5 and AMIP are the only sources whose raw isn't already on a cluster with
free compute + space. Stampede3's `ERA5/h5` is a *different* (non-Pangu) archive —
it is missing `mean_sea_level_pressure`, which is why job 3290922 died — so ERA5
must come from Delta. This runbook moves the Delta raw to Stampede3, converts on
the `spr` queue, then consolidates onto the Derecho master + Stampede3 second copy.

**Master = Derecho scratch. Second copy = Stampede3 scratch.** Both are volatile
(60-/90-day purge), so the registry tracks every copy and `sync_dataset.py`
re-transfers a lost one.

---

## 0. One-time: fill the 3 Globus collection UUIDs

Look each up once at <https://app.globus.org/collections> (or `globus endpoint search`),
then replace the three `TODO-*-UUID` placeholders in
[`hpc/data_registry.yaml`](data_registry.yaml):

```yaml
clusters:
  delta:      { globus_collection: <NCSA Delta collection UUID> }
  derecho:    { globus_collection: <NCAR GLADE collection UUID> }
  stampede3:  { globus_collection: <TACC Stampede3 collection UUID> }
```

Authenticate once from wherever you run the CLI (your laptop is easiest —
`pipx install globus-cli && globus login`), or drive the same transfers from the
Globus web app. The transfers run server-side between endpoints; you do **not**
need to `ssh`/`kinit` into Delta for them.

Everything below is generated by the tooling — re-run any command with
`--dry-run` first to see the exact `globus transfer` line without executing it.

---

## 1. Stage the Delta raw → Stampede3

```bash
cd tools/data
python sync_dataset.py era5 --to stampede3 --stage-raw    # → $SCRATCH/raw/era5/h5data
python sync_dataset.py amip --to stampede3 --stage-raw    # → $SCRATCH/raw/amip
```

Each emits a single recursive `globus transfer` (whole archive, checksum sync so
re-runs are idempotent). With `globus` on PATH and real UUIDs, it submits the
transfer; otherwise it prints the command to run in the web app. Destinations are
exactly what the converters read (`RAW=` in the sbatch scripts).

Wait for both transfers to reach **SUCCEEDED** (`globus task list`) before Step 2.

## 2. Convert on Stampede3 (`spr`)

```bash
# on a Stampede3 login node, repo at $WORK/physicsnemo (ai-rossby)
sbatch hpc/scripts/convert_era5_stampede3.sbatch     # 1979-2024 + normalization
sbatch hpc/scripts/convert_amip_stampede3.sbatch     # 1978-2024
```

Both request a whole `spr` node (`-N1 -n1 -c112`) and size the H5 reader pool to
all 112 cores. `skip-if-exists`, so a re-submit resumes. Output →
`$SCRATCH/physicsnemo-zarr/{era5,amip}/<year>.zarr`.

Sanity-check the first year before trusting the whole run:

```bash
python - <<'PY'
import xarray as xr
ds = xr.open_zarr("$SCRATCH/physicsnemo-zarr/era5/1979.zarr")
print(ds.dims); print(list(ds.data_vars))       # expect mean_sea_level_pressure present
PY
```

## 3. Record the new copies, then replicate to the master

```bash
cd tools/data
python registry.py scan stampede3 --write   # records era5/amip copies now on Stampede3
python registry.py scan derecho   --write   # records plev/e3sm copies (once Derecho jobs finish)
```

Now every year-store's true locations are in the registry. Replicate so each
dataset lives on **both** master and second copy:

```bash
# ERA5 + AMIP: Stampede3 → Derecho master
python sync_dataset.py era5 --to derecho
python sync_dataset.py amip --to derecho

# PLASIM-plev + E3SM: Derecho master → Stampede3 second copy
python sync_dataset.py plasim_plev --to stampede3
python sync_dataset.py e3sm        --to stampede3
```

Then re-scan both clusters (`registry.py scan <cluster> --write`) so the new
copies are recorded.

### Stats stores (normalization / climatology-bias)

`sync_dataset.py` moves per-year stores; the small named stat stores travel in a
one-off batch. On the same `globus transfer <src>:<root> <dst>:<root> --batch -`
(same collections/roots as Step 3), feed:

```
era5/normalization_pangu_s2s.zarr        era5/normalization_pangu_s2s.zarr        --recursive
e3sm/normalization_2015-2050.zarr        e3sm/normalization_2015-2050.zarr        --recursive
e3sm/climatology_bias.zarr               e3sm/climatology_bias.zarr               --recursive
```

(AMIP normalization stays `.nc`; the recipe reads it directly — copy
`raw/amip/*_mean.nc,*_std.nc` alongside if training off Stampede3.)

## 4. Verify

```bash
python registry.py check      # every dataset "ok"; no MISSING, no single-copy AT-RISK
```

A green `check` means all six datasets are on the master **and** a second copy,
and any purge is recoverable with `sync_dataset.py --rehydrate <cluster>`.

---

## Rehydrate after a purge (ongoing)

If a scratch purge eats the master or the second copy:

```bash
python tools/data/sync_dataset.py --rehydrate derecho     # or: stampede3
```

It reads the registry, scans what's actually present, and re-pulls only the
missing year-stores from a peer that still has them.
